**Почему 48K, а не 100K как у Qwen (ключевая находка):**
- **Архитектура GLM-4.7-Flash в GGUF = `deepseek2` (MLA-внимание)**, нативный контекст ~202752, «думающая» (`<think>` вкл. по умолчанию). Билд b9851 её грузит без проблем (арх давно поддержана).
- **100K целиком в 16 ГБ НЕ влезает без спилловера.** Хоть модель (13.6 ГиБ) и меньше 16 ГБ, при `-c 102400` idle VRAM ~15790 MiB, и во время prefill транзитный scratch перебивает потолок 16303 → **WDDM тихо сливает часть в системную RAM по PCIe → катастрофа: pp ~31, tg ~2.3 tok/s** (в 30× медленнее). Симптом: сервер «healthy», но инференс ползёт. Лечится только снижением VRAM-давления.
- **VRAM растёт по контексту НЕЛИНЕЙНО** (замерено, ub512, full-GPU): 32768→15284 · **49152→15630 (peak 15708, ОК)** · 65536→15786 (спилл) · 102400→15790 (спилл). Обрыв («cliff») спилловера — около **idle ~15.75 ГиБ**. `-ub` тоже жрёт VRAM (буфер prefill): ub2048 при 65536 уже даёт 15798 (спилл), поэтому оставлен **ub512** — и его хватает, prefill всё равно ~3900+ (модель целиком на GPU, не bandwidth-bound как у Qwen).
- **Профили с полным контекстом через оффлоад экспертов `--n-cpu-moe`** (все замерены). Ключ: при 128K обязателен `-ub 512`, иначе prefill-буфер даёт спилловер. Полное среднее по 9 прогонам сделано только для выбранного 128K/ncmoe8; остальные — одиночные пробники (холодные, prefill занижен ~на 15–20% против warmup-среднего):
>   - **128K + `--n-cpu-moe 8` + ub512 (ВЫБРАН)** → pp **2350.6** / tg **87.5** (n=9), idle VRAM 15789 / пик 15822 (запас ~480 MiB).
