# Транскрибация созвонов: ASR + диаризация + выжимка

Разовый пайплайн под запись созвона `созвон_пацаны_ракета_29_июля.m4a`
(4:48:39, 3 участника, русская речь с англотерминами). Всё локально.

ASR и диаризация — на ПК (RTX 5070 Ti). Выжимка — с макбука через прод-LLM
(`qwen3.6-35b-a3b` за llama-swap, см. [../docs/current-setup.md](../rigs/rtx5070ti-16gb/current-setup.md)).

## Что за файлы

| Файл | Где гоняется | Что делает |
|---|---|---|
| `setup-pc.ps1` | ПК | Установка стека пошагово, с контрольными точками |
| `check-env.py` | ПК | Диагностика: torch/CUDA/sm, ctranslate2, cuDNN, HF_TOKEN |
| `01-asr.py` | ПК | wav → `asr.json`. Про спикеров не знает |
| `01b-align.py` | ПК | `asr.json` → `asr_aligned.json` с пословными таймкодами |
| `02-diarize.py` | ПК | wav → `diar.rttm`. Про текст не знает |
| `03-merge.py` | любая | `asr_aligned.json` + `diar.rttm` → `transcript.md`, `turns.json` |
| `04-summarize.py` | макбук | `turns.json` → `summary/outline.md`, `summary/summary.md` |
| `audio_io.py` | — | Чтение WAV через stdlib, без ffmpeg и torchaudio |
| `glossary.json` | — | Термины: подсказка Whisper + словарь замен + справка для LLM |

## Замеры на реальной записи (4:48:39, 3 участника, Zoom-микс)

| Стадия | Время | Заметки |
|---|---|---|
| ASR large-v3 fp16, batch 16 | **616 с** | 28x realtime, 710 сегментов, ~70k токенов |
| Выравнивание wav2vec2 | **120 с** | 35408 слов, 100% с таймкодом |
| Диаризация pyannote 3.1 | **222 с** | пик VRAM 3 ГБ, 4542 отрезка |
| Мерж | секунды | 928 реплик, медиана 7 с |
| Выжимка map-reduce | ~10 мин | 17 чанков + 2 reduce |

## Почему стадиями, а не одной командой `whisperx`

4:48 одним куском — это один длинный провал: упадёт на диаризации (а она рискованнее
всего), и весь ASR придётся гнать заново. Раздельные процессы дают ещё и то, что пики
VRAM Whisper и pyannote не складываются.

Мерж вынесен отдельно намеренно: имена спикеров, словарь замен и пороги склейки
правятся там, а значит переигрываются за секунды, без повторного ASR.

## Порядок

### 0. Подготовка аудио (макбук)

```bash
ffmpeg -i созвон.m4a -vn -ac 1 -ar 16000 -c:a pcm_s16le call.wav
# три среза, каждый со своей задачей
ffmpeg -ss 01:30:00 -t 00:02:00 -i созвон.m4a -vn -ac 1 -ar 16000 -c:a pcm_s16le pilot_short.wav
ffmpeg -ss 01:30:00 -t 00:10:00 -i созвон.m4a -vn -ac 1 -ar 16000 -c:a pcm_s16le pilot_mid.wav
ffmpeg -ss 00:00:00 -t 00:10:00 -i созвон.m4a -vn -ac 1 -ar 16000 -c:a pcm_s16le pilot_intro.wav
```

- `pilot_short` (2 мин) — дымовой: просто запускается ли всё. Итерация ~15 с,
  так что отлаживать падения дёшево.
- `pilot_mid` (10 мин, из середины) — оценка качества и диаризации: все трое
  уже разговорились.
- `pilot_intro` (10 мин, с начала) — там представляются, отсюда берём имена.

Проверено, что каналы исходника идентичны (разница L−R = −91 dB), поэтому `-ac 1`
ничего не теряет.

### 1. Стек на ПК

Освободить VRAM — Qwen занимает 14.85 из 16 ГБ:

```powershell
schtasks /End /TN llama-server
taskkill /IM llama-swap.exe /F
```

Дальше по `setup-pc.ps1`: `Step1-Python` → **перезайти по SSH** → `Step2-Torch` →
`Step3-Whisperx` → `Step4-CheckCT2`.

Диагностика после каждого шага — `check-env.py`. Отдельным файлом, потому что
однострочники `python -c "..."` по SSH разваливаются: цепочка
bash → OpenSSH → PowerShell → Python съедает кавычки.

### Грабли, которые уже сработали

**whisperx откатывает torch на CPU-сборку.** Ставишь `torch 2.11.0+cu128`,
потом `pip install whisperx` — и он молча тянет свой пин `torch==2.8.0` с PyPI,
где Windows-колесо идёт без CUDA. `cuda.is_available()` становится `False`,
причём без единой ошибки в выводе pip. Лечится возвратом **тех же** версий, но
из cu128-индекса, и обязательно **после** whisperx:

```powershell
pip install --force-reinstall torch==2.8.0 torchaudio==2.8.0 torchvision==0.23.0 `
    --index-url https://download.pytorch.org/whl/cu128
```

Полезная деталь: ASR при этом всё равно работал бы на GPU. У CTranslate2 свой
CUDA-рантайм, он берёт `nvidia-cublas`/`nvidia-cudnn` из site-packages и про torch
ничего не знает — `ct2 cuda devices` показывал `1` даже на CPU-сборке torch.
На CPU уползли бы только alignment и диаризация.

**torchaudio 2.8 не читает файлы без ffmpeg.** Декодирование ушло в `torchcodec`,
который на Windows не поднимается без ffmpeg-DLL: `Could not find module
libtorchcodec_core7.dll`. Обошли в `02-diarize.py` — читаем WAV через stdlib
`wave` + numpy. Вход и так 16k mono PCM после ffmpeg, декодировать нечего.

**cuDNN для CTranslate2.** CT2 на Windows ищет cuDNN-DLL в `PATH`, а torch везёт
свои внутри `torch\lib`, где CT2 их не видит. Симптом: `Could not locate
cudnn_ops64_9.dll`. `01-asr.py` и `check-env.py` чинят это сами через
`os.add_dll_directory`, беря DLL из `site-packages/nvidia`.

Если стек всё же не соберётся — откат на **whisper.cpp с CUDA**: готовый
zip-бинарь, никакого Python для ASR, а ggml-стек на этой машине уже проверен в
бою (llama.cpp b9851 cuda-13.3).

### 2. HF-токен

Нужен **только чтобы скачать веса pyannote** — они под гейтом. Инференс полностью
локальный, аудио никуда не уходит, интернет нужен один раз.

Принять условия на `huggingface.co/pyannote/segmentation-3.0` и
`huggingface.co/pyannote/speaker-diarization-3.1`, затем `$env:HF_TOKEN = "hf_..."`.

### 3. Пилот на 10 минутах

```powershell
Step5-Pilot
```

Чеклист — каждый пункт стоит час, если всплывёт на четырёх часах:

- `float16` не падает на sm_120 (`int8` падает с `CUBLAS_STATUS_NOT_SUPPORTED`);
- английские термины остались латиницей — ровно то, на чём отвалился GigaAM v3;
- `initial_prompt` реально подействовал: в батчевом режиме whisperx он исторически
  то работал, то молча игнорировался;
- pyannote нашёл ровно 3 голоса;
- нет повторяющихся сегментов (`03-merge.py` их схлопывает и помечает, но лучше
  чтобы их не было).

Заодно дешёвое сравнение, которое на пилоте стоит пять минут, а на полном файле —
часы: **large-v3 против large-v3-turbo**.

**Выравнивание (`01b-align.py`) не отключать.** Соблазн есть — кажется, что для
сводки хватит посегментной привязки. Не хватит: без пословных таймкодов спикер
назначается на весь 25-секундный кусок Whisper целиком, а диаризация различает
отрезки по ~2 с. На этой записи так вышло 72% сегментов с двумя-тремя
говорящими внутри и 16% речи, приписанной не тому человеку.

Опасение, что русская `wav2vec2-large-xlsr-53-russian` не знает латиницы и
испортит англотермины, на практике не подтвердилось: таймкод получили 35408
слов из 35408 (100%), а само выравнивание заняло 120 с на 4:48.

### 4. Полный прогон

```powershell
Step6-Full     # ~40-60 мин
```

Диаризация гонится **целиком по файлу**. Чанкать нельзя: метки `SPEAKER_XX`
локальны для запуска, `SPEAKER_00` из разных чанков — разные люди.

### 5. Опознание спикеров и мерж

```bash
python3 03-merge.py --samples          # характерные реплики каждого
python3 03-merge.py --map SPEAKER_00=Лёша SPEAKER_01=Федя SPEAKER_02=Женя
```

Опознаёт человек, а не LLM — по нескольким фразам это делается надёжнее.

### 6. Выжимка (макбук)

```powershell
schtasks /Run /TN llama-server    # поднять LLM обратно
```

```bash
python3 04-summarize.py --turns turns.json --out-dir summary/
```

16 чанков по ~20 мин с перекрытием 2 мин, ~7k токенов каждый. Чанковые выжимки
кэшируются в `summary/chunk-NN.md` — повторный запуск досчитывает недостающее.

На map-фазе thinking **выключен** (извлечение фактов механическое, рассуждения
только жгут время), на reduce — **включён**, там надо связывать и разрешать
противоречия.

Два выхода: `outline.md` — таймкодированное оглавление, и `summary.md` — решения,
задачи, открытые вопросы. На записи в 4:48 оглавление ценнее самой выжимки:
сводку из четырёх часов читать всё равно тяжело, а по оглавлению можно прыгнуть
в нужную минуту.

## Чего этот пайплайн не вытянет

Zoom микширует звук с AGC и подавлением неактивных говорящих: там, где двое
говорили одновременно, второй в записи прижат или потерян. Это ограничение
исходника, диаризация тут не поможет.

Единственная длинная пауза в записи — `2:15:09` (1м50с), похоже на перерыв.
Если кто-то на нём отходил и вернулся, стоит глянуть, не поплыли ли там метки.
