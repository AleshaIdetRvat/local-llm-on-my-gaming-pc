# Инструкции для агента

Инфра-репо (заметки, конфиги, бенч-скрипты — кодовой базы нет): локальный LLM-сервер
на игровом ПК с Windows и NVIDIA, раздающий OpenAI-совместимый API. Управляется агентом —
либо прямо на этом ПК, либо по SSH с другой машины.

## Первым делом — прочитай `rig.local.env`

```bash
cat rig.local.env
```

Там параметры конкретного стенда: режим работы, адрес API, путь установки, а для
сетевого режима — хост, юзер и ключ. Файл в `.gitignore`, у каждого свой.

**Если файла нет — не угадывай значения и не бери их из примеров в доках.**
Запусти скилл `rig-setup`: он проведёт пользователя по вопросам и заполнит файл.

### ⚠️ `RIG_MODE` меняет половину процедур

| | `local` | `ssh` |
|---|---|---|
| Где агент | на самом Windows-ПК | на другой машине |
| Команды к ПК | локальный PowerShell | `ssh -i $RIG_SSH_KEY $RIG_SSH_USER@$RIG_HOST '<powershell>'` |
| API | `127.0.0.1:8080` | `$RIG_HOST:8080` |
| Что не нужно | SSH-ключи, файрвол, VPN-грабли, scp | — |

Скрипты эту разницу уже прячут: `rig.py` даёт `pc_cmd()` и `api_base()`,
`bench/*.py` работают в обоих режимах без правок.

## Структура

| Путь | Что там |
|---|---|
| `docs/` | Переносимое знание: установка, подбор моделей, llama-swap, замеры, грабли Windows |
| `rigs/<стенд>/` | Всё машинно-специфичное: состояние прода, модели, замеры, история, зеркала конфигов |
| `templates/` | Шаблон `config.yaml` для llama-swap |
| `bench/` | Скрипты замеров (работают в обоих режимах) |
| `transcribe/` | Отдельный пайплайн: расшифровка созвонов WhisperX + pyannote, выжимка через локальную LLM |
| `rig.py` | Чтение `rig.local.env` + `pc_cmd()`, прячущий разницу режимов |
| `.agents/skills/` · `.claude/skills/` | Скиллы: `rig-setup`, `rig-model`, `rig-troubleshoot` |

Начинать чтение: `docs/README.md` — переносимое, `rigs/<стенд>/current-setup.md` — своё.

## Ключевое

- **Ошибка бюджета VRAM не даёт честной ошибки.** Сервер отвечает, но prefill падает
  в десятки раз. После каждой правки `-c` / `-ub` / `--n-cpu-moe` — замер,
  а не «вроде работает». Одно изменение за раз.
- **Конфиг моделей правим в зеркале** `rigs/<стенд>/pc-mirrors/config.yaml`, потом копируем
  на ПК. `--watch-config` подхватит сам, рестарт не нужен. В ssh-режиме файлы возить
  только через `scp` — `Get-Content` ломает UTF-8.
- **VRAM меряем во время генерации.** В простое WDDM вытесняет память процесса в RAM
  и цифра врёт в меньшую сторону — это не выгрузка модели.
- **SSH таймаутит** (ssh-режим) — сначала спроси про VPN на ПК, потом про профиль сети.
  Не лезь чинить ключи: за всю историю проекта дело ни разу не было в них.
- **Сервер не встал после включения ПК** — спроси, выключал пользователь ПК или
  перезагружал. Fast Startup не даёт сработать триггеру At Startup.

## ⚠️ Репозиторий публичный

Всё, что ты сюда пишешь, видно посторонним. Тексты в этом репо пишет агент, а не
человек, — значит следить за этим тоже тебе.

**Идентификаторы машины в коммиты не попадают:** IP, хостнейм, SSID, имя SSH-юзера,
путь к ключу. В доках и чекпоинтах пиши `$RIG_HOST`, `$RIG_API` и так далее либо
обобщённо («хост ПК», «домашняя подсеть»). Живые значения живут только в `rig.local.env`,
который в `.gitignore`.

Особенно легко проколоться в чекпоинте: туда так и просится вставить команду,
которую ты только что выполнил, — вместе с реальным адресом.

**Перед каждым коммитом:**

```bash
git add -A && python3 rig.py --check
```

Проверка ищет значения из `rig.local.env` в проиндексированных файлах и выходит с
кодом 1, если нашла. `python3 rig.py --check --all` — то же по всем отслеживаемым файлам.

## Конвенции

- После значимых изменений: чекпоинт `rigs/<стенд>/history/ГГГГ-ММ-ДД-слаг.md` —
  самодостаточный: что сделали, почему, что показали замеры, как откатить.
  Плюс обновить `current-setup.md`, а если менялись модели — `models.md`.
- Историю не переписываем, только дописываем новые файлы. Устаревший чекпоинт
  остаётся как есть; актуальное состояние живёт в `current-setup.md`.
- Замеры записываем с контекстом: глубина промпта, тёплый прогон или холодный,
  пик VRAM во время генерации, полная строка запуска модели.
- Зеркала в `pc-mirrors/` держим байт-в-байт с ПК; на ПК перед правкой — бэкап `*.bak-<тема>`.
- Правки в `docs/` — только переносимое. Всё, что верно лишь для одной машины,
  идёт в `rigs/<стенд>/`.
- **После завершения блока изменений — git-коммит** (Conventional Commits, сообщение
  на русском), предварительно прогнав `python3 rig.py --check`.
  Не оставлять рабочее дерево грязным в конце сессии.

### ⚠️ Скиллы лежат в двух папках-близнецах

`.agents/skills/` — кросс-агентный стандарт (Codex, Cursor, Gemini CLI и другие).
`.claude/skills/` — Claude Code читает только её.

**Содержимое должно быть идентичным.** Правишь скилл в одной папке — сразу копируй
в другую целиком:

```bash
rsync -a --delete --exclude='.system/' .agents/skills/ .claude/skills/   # macOS / Linux
diff -r --exclude='.system' .agents/skills .claude/skills                # проверка
```

```powershell
robocopy .agents\skills .claude\skills /MIR /XD .system                  # Windows
```

Симлинк тут не годится: git на Windows по умолчанию выкачивает его текстовым файлом
(`core.symlinks=false` на NTFS), а Windows — основная платформа этого репо.
Осознанный костыль до тех пор, пока Claude Code не научится читать `.agents/skills/`
([issue #31005](https://github.com/anthropics/claude-code/issues/31005)).
