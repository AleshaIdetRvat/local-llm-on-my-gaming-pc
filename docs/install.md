# Установка с нуля

Ставим на игровой ПК с Windows 11 и видеокартой NVIDIA: llama.cpp + модель +
llama-swap + автозапуск. На выходе — OpenAI-совместимый API, который переживает
перезагрузку и сам освобождает VRAM, когда ты хочешь поиграть.

Дальше предполагается, что `rig.local.env` уже заполнен
(если нет — скажи агенту «настрой стенд», это скилл `rig-setup`).

## Шаг 0. Префлайт

Проверь до того, как что-то качать:

```powershell
nvidia-smi                                  # видеокарта, версия драйвера, объём VRAM
Get-PSDrive C | Select-Object Free          # свободное место
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory
```

- **Место на диске.** Одна модель — это 7–25 ГБ. Считай минимум 30 ГБ, а если планируешь
  несколько моделей под llama-swap — 60–100 ГБ.
- **Драйвер NVIDIA.** Для карт 50-й серии (Blackwell) нужен ≥ 590. Для более старых
  подойдёт любой свежий.
- **RAM.** Важна, только если будешь выносить часть модели в оперативку (`--n-cpu-moe`).
  32 ГБ хватает, но впритык: эксперты в RAM плюс Windows плюс кэш загрузки.
  Перед первым запуском закрой игры и браузер.
- **⚠️ `nvidia-smi` показывает `CUDA Version` драйвера — это максимум, который он умеет,
  а не то, что у тебя установлено.** Откатывать драйвер не нужно; значение имеет только то,
  под какую CUDA собран бинарник llama.cpp (шаг 2).

Если агент будет ходить на ПК по сети — сейчас самое время поднять OpenSSH:
[remote-access.md](remote-access.md). В local-режиме пропусти.

## Шаг 1. Каталог

Всё хозяйство держим в одном месте — это `RIG_ROOT`, по умолчанию `C:\llm`:

```
C:\llm\
  llama.cpp\        бинарники движка
  llama-swap\       прокси + config.yaml
  models\           веса (по подпапке на модель)
```

Не клади это в `C:\Users\<имя>\...`, если имя пользователя кириллическое —
часть инструментов на таких путях спотыкается.

## Шаг 2. llama.cpp

Собирать не надо, есть готовые сборки в [GitHub Releases ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp/releases).
Нужны **два** архива, распаковать в одну папку `<RIG_ROOT>\llama.cpp\`:

- `llama-bXXXX-bin-win-cuda-<версия>-x64.zip` — сам движок;
- `cudart-llama-bin-win-cuda-<версия>-x64.zip` — рантайм CUDA (без него не стартует).

**⚠️ Версия CUDA в имени архива — не косметика.** Мы напоролись на то, что свежая
на тот момент сборка CUDA 13.x на Blackwell (sm_120) работала в разы медленнее и падала,
а сборка под CUDA 12.8 на той же машине была здорова. Симптом коварный: всё «работает»,
просто в несколько раз медленнее, чем должно.

Если видишь необъяснимо низкую скорость на новой карте — **попробуй сборку под предыдущую
мажорную CUDA**, прежде чем копать что-то ещё. Прогресс не стоит на месте, так что
конкретные номера версий проверяй на момент установки.

Проверка:

```powershell
C:\llm\llama.cpp\llama-server.exe --version
```

## Шаг 3. Скачать модель

Что именно качать — [choosing-models.md](choosing-models.md). Коротко: Q4-квант,
по возможности QAT- или UD-версия, размер файла с запасом под твою VRAM.

**Сверяй имя файла и его размер с живой карточкой модели на HuggingFace**, а не с тем,
что где-то написано: имена квантов меняются, а битый или не тот файл ты обнаружишь,
только когда llama.cpp упадёт с невнятной ошибкой.

Качать проще всего встроенным `curl.exe` — Python для этого не нужен:

```powershell
curl.exe -L -C - --speed-limit 1024 --speed-time 60 `
  -o C:\llm\models\<модель>\<файл>.gguf `
  https://huggingface.co/<репо>/resolve/main/<файл>.gguf
```

Флаги не для красоты: `-C -` возобновляет обрыв, а `--speed-limit`/`--speed-time` спасают
от зависшего, но формально живого соединения — иначе загрузка встаёт намертво,
и `--retry` этого не замечает. Подробности — [windows-notes.md](windows-notes.md#скачивание-больших-файлов-веса-моделей).

**Если качаешь по SSH — читай про job-объект** в [remote-access.md](remote-access.md#detached-процессы-умирают-вместе-с-ssh-сессией),
иначе загрузка умрёт вместе с сессией.

После скачивания сверь размер байт в байт с тем, что отдаёт HF.

## Шаг 4. Первый запуск и тюнинг

Стартуй **консервативно** — задача первого запуска не в скорости, а в том, чтобы
модель вообще загрузилась:

```powershell
C:\llm\llama.cpp\llama-server.exe `
  -m C:\llm\models\<модель>\<файл>.gguf `
  --host 127.0.0.1 --port 8080 `
  -ngl 999 -c 32768 -fa on `
  --cache-type-k q8_0 --cache-type-v q8_0 `
  -t <число физических ядер> -b 2048 -ub 512 `
  --jinja
```

Для MoE-модели крупнее VRAM добавь `--n-cpu-moe 30` (эксперты первых 30 слоёв — в RAM).

Дальше — петля тюнинга, по одному изменению за раз, с замером после каждого:

1. Снимай VRAM **во время генерации** (`nvidia-smi`), а не в простое.
2. Для MoE: снижай `--n-cpu-moe` (30 → 26 → 22…), пока занятая VRAM не подойдёт
   к потолку с запасом ~1 ГБ. Минимальное значение, которое ещё грузится, — рабочее.
3. Подними `-ub` (512 → 1024 → 2048): prefill может ускориться вдвое.
4. Подними `-c` до нужного контекста — помни, что KV аллоцируется целиком при старте.

**После каждого шага — замер** ([методика](benchmarks.md)). Ошибка бюджета VRAM
не даёт честной ошибки: сервер отвечает, но prefill падает в десятки раз.

Два флага, про которые стоит знать, но которые **не надо включать по умолчанию**:

- `--no-mmap` — грузит модель в RAM целиком вместо ленивого mmap, иногда ускоряет
  decode на CPU-оффлоаде. ⚠️ Известное ограничение апстрима: в RAM грузится **весь** файл,
  включая слои, уехавшие в VRAM, и эта память не освобождается. На 32 ГБ это прямой путь
  к свопу. Включать только при подтверждённом запасе RAM и обязательно с замером.
- `--mlock` — не даёт страницам модели уйти в своп. Имеет смысл, если после долгого
  аптайма видишь просадки. На Windows отдельных прав обычно не требует.

Когда цифры устраивают — запиши конфигурацию и замеры в `rigs/<свой-стенд>/`.

## Шаг 5. llama-swap

Одна модель — уже рабочий сервер. Но как только моделей станет две, руками их
перезапускать надоест: [llama-swap.md](llama-swap.md) объясняет, зачем он и как
устроен конфиг, шаблон лежит в [`templates/config.yaml`](../templates/config.yaml).

Коротко: скачай `llama-swap.exe` из [релизов](https://github.com/mostlygeek/llama-swap/releases)
в `<RIG_ROOT>\llama-swap\`, положи рядом `config.yaml`, перенеси в него отлаженную
строку запуска из шага 4 и запусти:

```bat
llama-swap.exe --config C:\llm\llama-swap\config.yaml --listen 127.0.0.1:8080 --watch-config > C:\Users\Public\llama-swap.log 2>&1
```

`--listen 0.0.0.0:8080` вместо `127.0.0.1` — если к API будут ходить с других машин
локальной сети (в ssh-режиме это обязательно). Тогда же понадобится правило файрвола.

## Шаг 6. Автозапуск

Чтобы сервер поднимался сам после включения ПК — задача планировщика.

**⚠️ Здесь лежат главные грабли всей установки: Fast Startup.** Обычное выключение
Windows 11 — это не настоящий boot, и триггер «At Startup» после него не срабатывает.
Сервер не встанет, и понять почему — небыстро. Нужны **два** триггера.
Готовый рецепт и объяснение — [windows-notes.md](windows-notes.md#fast-startup-ломает-автозапуск).

Заодно удобно сделать на рабочем столе два ярлыка — «включить LLM» и «выключить LLM»
(`schtasks /Run` и `/End` плюс `taskkill` по процессу), чтобы освобождать VRAM перед игрой
не через агента, а одним кликом.

## Шаг 7. Проверка

```bash
curl <RIG_API>/models
curl <RIG_API>/chat/completions -H "Content-Type: application/json" \
  -d '{"model":"default","messages":[{"role":"user","content":"привет"}]}'
```

Ключ API — любая непустая строка, аутентификации у llama-swap нет.
**Именно поэтому наружу этот порт выставлять нельзя** — только локальная сеть.

Дальше подключай что угодно, что умеет в OpenAI API: агентов, редакторы кода,
Open WebUI. Модель выбирается полем `model`; заведи алиас `default`, чтобы при смене
прод-модели не править клиентов.

## Что делать дальше

- Прогнать [полноценный замер](benchmarks.md) и записать цифры в `rigs/<свой-стенд>/benchmarks.md`.
- Добавить вторую модель под другой профиль задач ([choosing-models.md](choosing-models.md)).
- Завести чекпоинт в `rigs/<свой-стенд>/history/` — что сделал, что померил, как откатить.
