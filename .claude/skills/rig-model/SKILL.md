# Работа с моделями стенда

Обязательное чтение перед началом: `docs/choosing-models.md` (подбор под VRAM)
и `docs/llama-swap.md` (конфиг и его тонкости). Параметры стенда — в `rig.local.env`;
если его нет, сначала скилл `rig-setup`.

## ⚠️ Правило номер один

**Ошибка бюджета VRAM не даёт честной ошибки.** Сервер запустится, будет отвечать
и выглядеть здоровым, но prefill упадёт в десятки раз — веса поехали в RAM и ездят
по PCIe на каждый токен.

Поэтому: **одно изменение → один замер**. Не меняй `-c`, `-ub` и `--n-cpu-moe`
одновременно, иначе не поймёшь, что именно сломало скорость.

## Добавить модель

**1. Подобрать.** По `docs/choosing-models.md`, исходя из VRAM стенда
(смотри `rigs/<стенд>/current-setup.md`). Проверь, есть ли QAT- или UD-версия квантов —
это бесплатное качество. Предложи пользователю вариант с обоснованием, а не просто
«скачал вот эту».

**2. Сверить файл с живой карточкой HuggingFace.** Имя и точный размер в байтах —
через API, а не пересказом веб-страницы. Имена квантов меняются, а не тот файл
обнаружится, только когда llama.cpp упадёт с невнятной ошибкой.

**3. Скачать** через `curl.exe` на ПК — обязательно с `-C -` и `--speed-limit/--speed-time`
(`docs/windows-notes.md`). В ssh-режиме помни про job-объект: detached-процесс умрёт
вместе с сессией (`docs/remote-access.md`). После загрузки — сверить размер байт в байт.

**4. Вписать в конфиг.** Правь **зеркало в репо** — `rigs/<стенд>/pc-mirrors/config.yaml`,
а не файл на ПК напрямую. Затем скопируй на ПК:

- local: обычным копированием в `<RIG_ROOT>\llama-swap\config.yaml`;
- ssh: `scp` (не `Get-Content` — ломает UTF-8).

Перед перезаписью сделай на ПК бэкап: `config.yaml.bak-<тема>`.

`--watch-config` подхватит правку сам, рестарт не нужен.

**5. Проверить, что модель появилась:**

```bash
curl <RIG_API>/models
```

**6. Замерить** — `python3 bench/bench-ctx.py <model_id>`, предварительно добавив модель
в словарь `MODELS` в шапке скрипта (значение — потолок контекста из `-c`).
Методика и грабли — `docs/benchmarks.md`.

**7. Записать.** Карточка модели в `rigs/<стенд>/models.md`: репозиторий и точное имя файла,
строка запуска с объяснением неочевидных флагов, скорость, поведение thinking,
для чего эту модель брать. Цифры — в `rigs/<стенд>/benchmarks.md`.

**8. Чекпоинт и коммит** — см. конвенции в `AGENTS.md`.

## Перенастроить существующую (быстрее / больше контекста)

Тюнинг — это петля, а не одно действие:

1. Замерь текущее состояние — иначе не с чем будет сравнивать.
2. Поменяй **одно**: `--n-cpu-moe` вниз (быстрее, больше VRAM), `-ub` вверх
   (быстрее prefill, больше буферы) или `-c` вверх (больше контекст, больше KV).
3. Замерь снова.
4. Если prefill обвалился — откатись на предыдущее значение, это спилловер.
5. Повтори, пока следующий шаг не начнёт ломать.

VRAM смотри **во время генерации**: в простое WDDM вытесняет память процесса в RAM
и цифра врёт в меньшую сторону.

## Поменять прод-модель

Не меняй имя модели у клиентов. Перевесь алиас `default` в `config.yaml` на другую
запись — клиенты продолжат ходить по тому же имени.

## Модель с thinking

Помни две вещи из `docs/choosing-models.md`:

- JSON для `--chat-template-kwargs` **нельзя** передавать через `cmd:` — llama-swap
  не снимает кавычки. Только через `env: LLAMA_ARG_CHAT_TEMPLATE_KWARGS=...`.
- Поведение по умолчанию у разных шаблонов разное, и оно не всегда такое, как ждёшь.
  Проверь фактически: пришёл ли непустой `reasoning_content` в ответе.

Если нужны оба режима — заведи **две записи** на одни и те же веса, отличающиеся только
`enable_thinking`. Переключение между ними стоит перезагрузки модели.

## Убрать модель

Удали блок из `config.yaml`, синхронизируй зеркало, проверь `/models`.
Файл весов с диска удаляй только по явной просьбе пользователя — скачивать заново долго.
Карточку в `models.md` не стирай, а помечай как снятую с прода: почему сняли —
это ровно та информация, которой через полгода не хватит.
